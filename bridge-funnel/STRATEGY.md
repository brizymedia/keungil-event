# 큰길브리지 홈페이지 사업 — SNS 홍보 → 계약 자동화 전략

> 한 줄 요약: **스레드는 대화로 신뢰를 쌓고, 인스타는 댓글 키워드 → DM으로 연락처를 모으고, 유튜브는 검색으로 오래 남는다.**
> 세 채널 모두 같은 원고 한 벌(`sns/content.json`)을 쓰고, 모든 링크는 무료 자료 페이지 하나(`free/`)로 모인다.
> 그 뒤는 사람 손이 필요 없다: **무료 자료 → 내 가게 데모 → 자동 견적 → 전자계약 → 결제 → 자료 제출서.**

---

## 1. 왜 이 구조가 가장 효율적인가

| 문제 | 흔한 방식 | 이 구조 |
|---|---|---|
| 홍보 글을 매일 못 씀 | 생각날 때 올림 → 끊김 | 원고 30편 + 짧은 글 30편을 한 번 써 두고 **자동 예약 게시** (한 편을 캐러셀 · 스레드 · 쇼츠 · 릴스 4곳에 재활용) |
| 게시물은 보는데 문의가 없음 | 「DM 주세요」 | **댓글에 「전자책」** → 봇이 즉시 DM 링크 → 연락처 수집. 댓글이 늘어 노출도 같이 오른다 |
| 연락처를 받아도 영업을 못 함 | 전화 돌리기 | 자료 메일 + **1 · 3 · 6일 후속 메일 자동** · 데모 열람 알림(기존 데모 서버) |
| 「얼마예요?」 상담에 시간 소모 | 전화 상담 → 견적서 작성 | **가격 공개 + 자동 견적** — 고객이 직접 고른다 |
| 계약 · 입금 확인 번거로움 | 카톡으로 계약서 · 계좌 안내 | 견적이 그대로 **전자계약서**가 되고, 서명하면 **바로 결제 화면**. 무통장은 메일의 단추 한 번으로 확인 처리 |

사장님 시간은 두 곳에만 쓴다: **(1) 스레드 댓글에 사람 말투로 답하기(하루 10분), (2) 결제 들어온 고객의 홈페이지 제작.**

## 2. AI 검색 시대 메시지 — 모든 콘텐츠의 뼈대

**핵심 주장**: 손님은 검색 대신 AI에게 묻는다 → AI는 10곳이 아니라 2~3곳만 고른다 → 고르는 근거는 「읽을 수 있는 글」 → 그 글이 있어야 할 곳이 홈페이지.

반박에 대한 답(원고에 이미 반영):
- 「인스타 있으면 되지 않나?」 → 인스타는 사람을 모으는 곳, 홈페이지는 AI에게 가게를 설명하는 곳 (p03)
- 「플레이스 있으면 되지 않나?」 → 플랫폼은 월세, 홈페이지는 내 집 (p21)
- 「비싸지 않나?」 → 원페이지 10만원부터, 가격 전부 공개 (p11, p23)
- 「만들어도 검색 안 되던데」 → 검색 등록 5가지 (p08)

> 주의: 원고에는 출처 없는 통계(「AI 검색 이용자 ○○% 증가」 같은 숫자)를 일부러 넣지 않았습니다. 틀린 숫자 하나가 신뢰 전체를 깎습니다. 숫자는 큰길브리지 자체 실적(1,800회 행사 등)이나 예시로만 씁니다.

### 콘텐츠 비율 (30편 기준)
| 기둥 | 비율 | 역할 | 예 |
|---|---|---|---|
| AI 검색 교육 | 30% | 문제 인식 · 저장 · 공유 | p01 · p02 · p19 · p26 · p30 |
| 실전 팁 | 30% | 신뢰 (도움 먼저) | p04 · p05 · p06 · p08 · p22 |
| 업종별 | 20% | 「내 얘기네」 → 데모 신청 | p13 식당 · p14 인테리어 · p15 학원 · p16 미용 · p17 행사 · p18 병원 |
| 오퍼 | 20% | 전환 | p10 데모 · p11 견적 · p12 명함 · p20 진행 과정 · p29 고급형 |

### 훅(첫 줄) 공식 — 새 원고 쓸 때
1. **상식 뒤집기**: 「손님이 검색을 안 합니다.」
2. **1분 실험**: 「오늘 챗GPT에 이것만 물어보세요.」
3. **흔한 착각**: 「인스타 있으면 홈페이지 필요 없다?」
4. **업종 호명**: 「미용실 원장님, 가격을 「문의」로 두셨나요?」
5. **손실 회피**: 「AI 검색 시대에 제일 억울한 가게」

## 3. 채널별 역할과 운영 규칙

### 스레드 — 대화 · 신뢰 (하루 2회 자동)
- **08:52** 원고(캐러셀 5장 + 글, 링크 포함) · **20:07** 짧은 질문형 글(링크 없음 → 댓글 유도)
- 스레드는 **댓글이 달리는 글**이 멀리 퍼진다. 저녁 글은 일부러 질문으로 끝낸다.
- 키워드 답글(「전자책」 「데모」 「견적」 「명함」)에는 봇이 링크 답글을 단다(스레드는 DM API가 없다).
- **사장님 몫**: 키워드가 아닌 댓글에는 하루 한 번 직접 답글. (AI 응대를 켜면 질문형 댓글에 Claude가 짧은 초안 답을 단다 — `AI_REPLY=1`)
- **잠재 고객 찾기**: 매일 아침 「홈페이지 제작 · 홈페이지 추천 · 네이버 검색 안나와 …」 최근 글을 찾아 **사장님 메일로** 보낸다. 모르는 사람에게 자동 답글은 달지 않는다(스팸 · 정책 위반). 광고 말고 **도움되는 답**을 직접 달면 프로필 방문 → 무료 자료로 이어진다.

### 인스타그램 — 저장 · 키워드 DM (매일 캐러셀 + 주 3회 릴스)
- **12:10** 캐러셀(저장 · 공유용 정보 카드) / **화 · 목 · 토 19:13** 릴스(같은 원고 → 세로 영상 자동 생성)
- 모든 게시물 마지막 장: **「댓글에 ○○ 남기시면 DM으로 보내 드려요」**
- 봇이 30분마다 댓글을 읽어 키워드면 **비공개 답장(DM) 1통 + 「DM 드렸어요」 답글**. (인스타 정책상 댓글 1개당 DM 1통, 댓글 후 7일 안)
- 프로필 링크: `free/?utm_source=instagram&utm_medium=bio`

### 유튜브 — 검색 · 오래 남는 자산
- **월 · 수 · 금 18:17** 쇼츠 자동 업로드(원고 재활용)
- **사장님 몫(주 1편, 선택)**: 5~8분 화면 녹화 실습 영상. 유튜브는 그 자체가 검색엔진이고, 설명이 잘 된 영상은 AI 답변의 출처로도 쓰인다. 추천 주제:
  1. 챗GPT에 우리 가게 물어보기 — 나오는 가게 vs 안 나오는 가게 차이
  2. 네이버 서치어드바이저 등록 따라하기 (10분)
  3. 구글 서치 콘솔 + 빙 웹마스터 한 번에 등록
  4. 가게 소개 한 문장 공식 — 업종별 10개 고쳐 보기
  5. 10만원 원페이지 홈페이지 만드는 과정 (타임랩스)
  6. 자주 묻는 질문(FAQ) 페이지 30분 만에 만들기
  7. 인스타 · 블로그 · 플레이스를 홈페이지로 모으는 법
  8. 실제 고객 홈페이지 전후 비교 (동의 받고)
  - 영상 설명란 첫 줄에 무료 자료 링크(`utm_source=youtube`), 고정 댓글에 같은 링크.

## 4. 퍼널과 목표 숫자

```
노출 ──▶ 무료 자료 페이지 ──▶ 신청(리드) ──▶ 데모 열람 ──▶ 자동 견적 ──▶ 계약서 서명 ──▶ 결제
         (free/)              (연락처)       (welcome/)     (go/)          (contract)      (pay/)
```

아래는 **출발 가정치**입니다. 2주 운영 후 매일 아침 오는 「자동영업 현황」 메일의 실제 숫자로 바꾸세요.

| 단계 | 가정 전환율 | 월 1,000명 방문 시 |
|---|---|---|
| 랜딩 → 신청 | 15% | 150명 |
| 신청 → 데모 열람 | 60% | 90명 |
| 데모 → 견적 완료 | 20% | 18명 |
| 견적 → 서명 | 40% | 7명 |
| 서명 → 결제 | 80% | 6건 |

**어디가 새는지 보고 고칠 곳**
- 랜딩 → 신청이 낮다 → 훅 · 전자책 제목 · 폼 칸 수를 바꾼다
- 신청 → 데모가 낮다 → 자료 메일 제목, 문자 알림(솔라피) 켜기
- 데모 → 견적이 낮다 → 3일차 후속 메일의 혜택(`PROMO`) 추가, 데모 품질 개선
- 견적 → 서명이 낮다 → 가격 저항: 베이직 강조 / 사장님 전화 한 통(대장 시트의 「견적 완료」 단계 고객)
- 서명 → 결제가 낮다 → 24시간 뒤 결제 안내 메일은 자동. 무통장 비중이 높으면 가상계좌 추천

## 6. 지켜야 할 규칙 (자동화라서 더 중요)

- **광고성 메일 · 문자** (정보통신망법 제50조): 수신 동의한 사람에게만, 제목에 `(광고)`, 본문에 수신거부 링크, 밤 9시~아침 8시 발송 금지. → 후속 메일은 동의(Y)한 사람에게만, 08~21시에만 가고, 제목 · 수신거부가 들어가 있다.
- **개인정보**: 수집 항목 · 목적 · 보관 기간을 폼에 명시했다. 대장 시트는 사장님 구글 드라이브에만 있다. 공개 저장소(GitHub)에는 고객 정보를 남기지 않는다.
- **인스타 DM**: 댓글 단 사람에게 1회 비공개 답장만(메타 정책). 모르는 사람에게 먼저 DM을 보내는 기능은 넣지 않았다.
- **스레드**: 모르는 사람 글에 자동 답글 금지. 잠재 고객 글은 메일로만 받아 사람이 답한다.
- **유튜브 API**: 심사 전(미인증) 프로젝트로 올린 영상은 **비공개로 잠긴다**. 공개 업로드는 구글 API 감사(audit) 통과 후. 그 전에는 `YT_PRIVACY=private` 로 올리고 스튜디오에서 공개로 바꾸거나, 감사를 신청하세요.
- **전자상거래 표시**: 결제 화면 하단에 사업자 정보 · 환불 규정(계약서 제12조)을 표시했다. 토스 심사에 필요하다.
- **의료 · 건강 업종 원고**: 과장 · 비교 · 치료 경험담 금지(p18에 반영).
