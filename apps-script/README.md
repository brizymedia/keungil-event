# 행사 사진 업로드 — 설치 안내

행사 사진을 휴대폰에서 올리면 **갤러리에 바로 쌓이고, 원본은 구글 드라이브에 보관**되는 시스템입니다.

새로 만들 계정은 없습니다. 이미 쓰시는 **구글 계정**과 **깃허브 계정**만 있으면 됩니다.
비용도 들지 않습니다.

전체 30분 정도 걸립니다. 한 번만 하시면 됩니다.

---

## 준비물 — 값 4개

설치하면서 아래 4개를 만듭니다. 다 만들면 마지막에 한 곳에 모아 넣습니다.

| | 무엇 | 어디서 |
|---|---|---|
| ① | 업로드 비밀번호 | 직접 정하시면 됩니다 |
| ② | 구글 드라이브 폴더 ID | 2단계 |
| ③ | 깃허브 토큰 | 3단계 |
| ④ | 저장소 이름 | `brizymedia/keungil-event` (그대로 쓰시면 됩니다) |

> **중요** — ①②③ 은 채팅창이나 메모장에 남기지 마시고, 구글 화면에 바로 넣어주세요.

---

## 1단계 · 앱스 스크립트 만들기

1. [script.google.com](https://script.google.com) 접속 (구글 계정 그대로 로그인)
2. 왼쪽 위 **「새 프로젝트」** 클릭
3. 화면 가운데 코드칸에 원래 있던 내용을 **전부 지우고**,
   이 폴더의 **`Code.gs`** 내용을 **전부 복사해서 붙여넣기**
4. 왼쪽 위 프로젝트 이름을 `YM 사진 업로드` 로 바꾸기 (안 바꿔도 됩니다)
5. 💾 저장

---

## 2단계 · 드라이브 폴더 만들기 → ② 폴더 ID

1. [drive.google.com](https://drive.google.com) 에서 폴더를 하나 만듭니다.
   이름 예) **`YM 행사 사진 원본`**
2. 그 폴더를 **두 번 눌러 들어갑니다**
3. 주소창을 보면 이렇게 생겼습니다:

   ```
   https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz
                                          └────── 이 부분이 폴더 ID ──────┘
   ```

4. `folders/` **뒤에 오는 긴 글자**를 복사해 둡니다 → 이게 **②** 입니다

행사별 하위 폴더(`2026-08-29 순창 고추장 축제` 같은)는 **자동으로 만들어집니다.**

---

## 3단계 · 깃허브 토큰 만들기 → ③ 토큰

사진을 홈페이지 저장소에 넣기 위한 열쇠입니다.

1. 깃허브에서 [Settings → Developer settings → Personal access tokens → **Fine-grained tokens**](https://github.com/settings/personal-access-tokens/new) 로 들어갑니다
2. 아래처럼 채웁니다

   | 항목 | 값 |
   |---|---|
   | Token name | `YM 사진 업로드` |
   | Expiration | `No expiration` 또는 1년 |
   | Repository access | **Only select repositories** → `keungil-event` 선택 |
   | Permissions → Repository permissions → **Contents** | **Read and write** |

3. 맨 아래 **Generate token** 클릭
4. 화면에 나오는 `github_pat_...` 글자를 복사해 둡니다 → 이게 **③** 입니다

> 이 토큰은 **한 번만 보입니다.** 창을 닫으면 다시 볼 수 없으니 바로 4단계로 넘어가세요.
> 잃어버려도 괜찮습니다 — 새로 만들면 됩니다.

---

## 4단계 · 값 4개 넣기

1. 앱스 스크립트 화면 왼쪽 **⚙️ 프로젝트 설정** 클릭
2. 아래로 내려 **「스크립트 속성」** → **「스크립트 속성 추가」**
3. 아래 4개를 하나씩 추가합니다 (이름은 **영문 대문자 그대로**)

   | 속성 이름 | 값 |
   |---|---|
   | `UPLOAD_PW` | ① 직접 정한 업로드 비밀번호 |
   | `DRIVE_FOLDER` | ② 드라이브 폴더 ID |
   | `GITHUB_TOKEN` | ③ 깃허브 토큰 (`github_pat_...`) |
   | `GITHUB_REPO` | `brizymedia/keungil-event` |

4. **저장**

---

## 5단계 · 배포하기

1. 오른쪽 위 파란 **「배포」** → **「새 배포」**
2. 왼쪽 ⚙️ 톱니바퀴 → **「웹 앱」** 선택
3. 아래처럼 맞춥니다

   | 항목 | 값 |
   |---|---|
   | 설명 | `1차` (아무거나) |
   | 다음 사용자로 실행 | **나** |
   | 액세스 권한이 있는 사용자 | **모든 사용자** ← ⚠️ 꼭 이걸로 |

4. **배포** 클릭
5. 권한 요청 창이 뜹니다 → **액세스 승인** → 본인 구글 계정 선택
   - "Google에서 확인하지 않은 앱" 경고가 나오면
     **고급 → (프로젝트 이름)(으)로 이동** 을 누르시면 됩니다.
     대표님이 직접 만든 스크립트라 정상입니다.
6. **웹 앱 URL** 이 나옵니다. `.../exec` 로 끝나는 주소입니다 → **복사**

---

## 6단계 · 잘 됐는지 확인

복사한 주소를 **브라우저 주소창에 그대로 붙여넣고 접속**해 보세요.
이런 글자가 나오면 성공입니다.

```json
{"ok":true,"이름":"YM 사진 업로드 서버",
 "설정완료":{"UPLOAD_PW":true,"GITHUB_TOKEN":true,
             "GITHUB_REPO":true,"DRIVE_FOLDER":true}}
```

4개가 전부 `true` 여야 합니다. `false` 가 있으면 4단계에서 그 값이 빠진 것입니다.

---

## 7단계 · 업로드 페이지에 연결

1. 휴대폰으로 **`큰길이벤트.com/ym토탈이벤트/upload.html`** 접속
   (자주 쓰실 페이지이니 **홈 화면에 추가**해 두세요)
2. 맨 위 「처음 한 번만 설정」 칸에 5단계에서 복사한 **웹 앱 주소** 붙여넣기 → 저장
3. 사진 몇 장으로 시험해 보세요

---

## 쓰는 법

1. 행사명·날짜·장소 입력 (직전에 쓴 행사명은 기억해 둡니다)
2. 사진 고르기 — 여러 장 한꺼번에 됩니다. 고르는 즉시 웹용으로 줄여둡니다
3. 비밀번호 넣고 **「갤러리에 올리기」**
4. 끝나면 **홍보 문구**가 자동으로 만들어집니다 → 복사하거나 「사진과 함께 공유」로 인스타·블로그 앱에 바로 넘기기

**원본 백업** 은 기본으로 켜져 있습니다. 데이터가 약한 현장에서는 꺼두시면 훨씬 빨리 올라갑니다
(끄면 웹용 축소본만 올라가고 원본은 남지 않습니다).

## 자주 겪는 문제

**"UrlFetchApp.fetch를 호출할 수 있는 권한이 없습니다"**
→ 구글이 「바깥 인터넷 연결」 권한을 안 받아간 상태입니다. 코드 문제가 아닙니다.

1. 앱스 스크립트 편집기 위쪽 **함수 목록**에서 **`권한받기`** 를 고르고 **「실행」**
2. 권한 요청 창이 뜨면 승인
   ("확인하지 않은 앱" 경고 → **고급 → (프로젝트 이름)(으)로 이동 → 허용**)
3. **「배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포」**

함수 목록에 `권한받기` 가 없으면 코드가 예전 것입니다.
목록에 있는 **`깃허브`** 를 대신 실행하셔도 같은 권한 창이 뜹니다.
(값 없이 부르는 것이라 실행 결과에 빨간 오류가 나오는 건 정상입니다. 권한 창을 띄우는 게 목적입니다)

**그래도 권한 창이 안 뜨면** — 구글이 "이미 다 승인됨"으로 착각하는 경우입니다.
필요한 권한을 코드에 못 박아 두면 확실히 다시 물어봅니다.

1. 편집기 왼쪽 **⚙️ 프로젝트 설정** → **「appsscript.json 매니페스트 파일을 편집기에 표시」** 체크
2. 왼쪽 파일 목록에 생긴 **`appsscript.json`** 클릭
3. 내용을 전부 지우고 이 폴더의 **`appsscript.json`** 내용을 붙여넣기 → 저장
4. 함수 하나를 **실행** → 권한 승인
5. **「배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포」**

그래도 안 되면 [myaccount.google.com/permissions](https://myaccount.google.com/permissions) 에서
해당 프로젝트를 찾아 **액세스 권한 삭제** 후, 위 4~5 를 다시 하시면 확실히 새로 물어봅니다.

**"서버가 이상한 답을 보냈습니다"**
→ 5단계에서 **「액세스 권한이 있는 사용자」를 「모든 사용자」** 로 안 하신 경우입니다.
　「배포 → 배포 관리」에서 연필 아이콘을 눌러 고치고 **새 버전**으로 다시 배포하세요.

**"비밀번호가 다릅니다"**
→ 4단계의 `UPLOAD_PW` 값과 업로드 페이지에 넣은 비밀번호가 다릅니다.

**"깃허브 저장소 실패 (401)"** 또는 **(403)**
→ 토큰이 만료됐거나 권한이 모자랍니다. 3단계를 다시 해서 새 토큰을 만들고
　`GITHUB_TOKEN` 값을 바꿔주세요. (Contents 를 **Read and write** 로)

**"원본 백업 실패"**
→ 사진 자체는 이미 올라갔습니다. `DRIVE_FOLDER` 값이 잘못됐거나 폴더가 지워진 경우입니다.

**갤러리에 사진이 안 보임**
→ 사진 목록이 퍼지는 데 최대 5분 걸립니다. 잠시 뒤 새로고침해 보세요.

**코드를 고친 뒤 반영이 안 됨**
→ 앱스 스크립트는 저장만으로는 안 바뀝니다.
　「배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포」 를 해야 반영됩니다.

## 나중에 붙일 것 — 인스타그램 자동 게시

지금은 「사진과 함께 공유」로 앱에 넘기는 방식입니다.
인스타그램 **완전 자동 게시**도 가능한데, 준비가 더 필요합니다.

- 인스타그램을 **프로페셔널 계정**으로 전환
- 페이스북 페이지와 연결
- 페이스북 개발자 앱 등록 + 토큰 발급

인스타그램은 "이 주소의 사진을 가져가라"는 방식이라 **공개된 사진 주소**가 필요한데,
지금 구조에서 그 주소가 이미 만들어집니다. 준비되시면 그때 이어서 붙이면 됩니다.

**네이버 블로그는 자동 게시가 불가능합니다.** 네이버가 글쓰기 API 를 없앴습니다.
로그인을 흉내내는 방법은 약관 위반이라 권하지 않습니다.
블로그는 「사진과 함께 공유」로 넘기는 방식이 최선입니다.
