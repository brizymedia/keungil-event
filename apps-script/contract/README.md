# 큰길이벤트기획 전자계약 서버 설치 (Google Apps Script)

`contract.html` 이 사용하는 무료 백엔드입니다. 설치하면 다음이 자동으로 됩니다.

- 고객 서명 링크를 **짧은 링크**(`contract.html?c=ABCD1234&s=…`)로 발급
- 고객이 서명하면 **도장 + 서명이 들어간 PDF** 자동 생성 → 내 드라이브 `큰길이벤트기획 계약서/연도/` 에 저장
- **양측 이메일**(회사 + 고객)로 PDF 첨부 발송
- 스프레드시트 **계약 대장** 자동 기록 (계약번호 · 행사 · 갑 · 금액 · 서명자 · 서명시각 · PDF · 문서확인코드)

서버 없이도 `contract.html`은 동작하지만(긴 링크 + 메일로만 서명 정보 전달), 계약 업무용으로는 서버 설치를 권장합니다.

---

## 1) 스크립트 만들기 (5분)

1. https://script.google.com → **새 프로젝트**
2. 기본으로 열린 `Code.gs` 내용을 모두 지우고, 이 폴더의 **`Code.gs`** 내용을 붙여넣기
3. 위쪽 설정값 확인
   - `COMPANY_EMAIL` : 서명본을 항상 받을 회사 메일 (기본 `gilauto325@gmail.com`)
   - 나머지는 그대로 두어도 됩니다
4. 프로젝트 이름: `큰길 전자계약` 등으로 저장

## 2) 웹앱으로 배포

1. 우측 상단 **배포 → 새 배포**
2. 톱니바퀴 → 유형 **웹 앱**
3. 설정
   - 설명: `contract v1`
   - **다음 사용자로 실행: 나**
   - **액세스 권한: 모든 사용자**  ← 고객 폰에서 열어야 하므로 반드시 "모든 사용자"
4. **배포** → 권한 승인 창에서 계정 선택 → "고급 → 안전하지 않은 페이지로 이동" → 허용
   (드라이브 · 스프레드시트 · 메일 권한을 씁니다)
5. 표시되는 **웹 앱 URL** 복사
   `https://script.google.com/macros/s/AKfycb…/exec`

## 3) contract.html 에 연결

방법 A (권장) — 관리자 화면에서 한 번만 입력
1. `https://큰길이벤트기획.com/contract.html?admin=1` 열기
2. 왼쪽 패널 **「우리 회사 정보 · 서버 설정」** 펼치기
3. **계약 서버 주소** 칸에 웹 앱 URL 붙여넣기 → **회사 정보 저장**
   (같은 칸에서 대표자 · 사업자등록번호 · 입금 계좌도 채워두세요 — 계약서에 인쇄됩니다)

방법 B — 파일에 고정
`contract.html` 상단 `const 서버주소_기본 = '';` 에 URL 을 넣어 배포

> 링크에는 배포 ID(`&s=…`)가 함께 실리므로, 고객 기기에서는 별도 설정이 필요 없습니다.

## 4) 도장 이미지

사이트 루트에 **`stamp-keungil.png`** (배경 투명, 정사각형, 600px 이상 권장) 를 올리면 을 서명란에 자동으로 찍힙니다.
파일이 없으면 임시로 CSS 로 그린 원형 도장이 표시됩니다.

---

## 사용 흐름

1. `quote.html?admin=1` 에서 견적 확정 → **「이 견적으로 계약서 작성」** → `contract.html?admin=1` 이 열리며 견적 내용이 채워짐
2. 갑 정보 · 행사 · 지급조건 · 취소규정 · 특약 확인/수정
3. **「고객 서명 링크 만들기」** → 링크 복사 / 카톡·문자 / 이메일로 전송
4. 고객: 폰에서 링크 열기 → 계약서 확인 → 서명 → 두 가지 동의 체크 → **「서명하고 계약서 보내기」**
5. 자동: PDF 생성 → 드라이브 저장 → 회사·고객 메일 발송 → 대장 기록
6. 고객이 같은 링크를 다시 열면 "서명 완료" 상태와 PDF 링크가 보입니다

## 코드를 고친 뒤 재배포

**배포 → 배포 관리 → (연필) → 버전: 새 버전 → 배포**
URL 은 그대로 유지됩니다. (새 배포를 만들면 URL 이 바뀌니 주의)

## 문제 해결

| 증상 | 확인 |
|---|---|
| 「서버 응답을 읽을 수 없습니다」 | 배포 액세스 권한이 "모든 사용자"인지 확인. 새 버전으로 재배포 |
| 고객 폰에서 「계약서를 불러오지 못했습니다」 | 링크가 잘렸는지(문자 길이) 확인 → 카톡·이메일로 다시 전송 |
| PDF 가 안 만들어짐 | 실행 기록(Apps Script → 실행) 확인. HTML 이 너무 크면 `contract.html` 의 도장 이미지를 줄이세요 |
| 메일이 안 옴 | 스팸함 확인. Gmail 일일 발송 한도(무료 100통/일) 초과 여부 |
| 도장이 안 보임 | `stamp-keungil.png` 파일명·위치 확인 (사이트 루트) |

## 데이터 위치

- 드라이브 `큰길이벤트기획 계약서/`
  - `_data/ID.json` : 계약 원문 · 상태 · 서명 메타 (지우지 마세요 — 링크가 이걸 읽습니다)
  - `연도/계약서_….pdf`, `서명_….png`
  - `계약 대장` (스프레드시트)

## 법적 효력 참고

전자서명법 제3조에 따라 당사자 간 약정으로 전자서명은 서명·날인의 효력을 가집니다. 이 시스템은 서명 시각, 서명자 정보, 문서 확인 코드(SHA-256), 기기 정보를 함께 기록하고 양측에 사본을 교부하는 방식으로 이를 뒷받침합니다.
관공서·대기업 계약처럼 공인인증(휴대폰 본인확인 등)이 요구되는 경우에는 모두싸인·글로싸인 등 인증 기반 서비스 병행을 권장합니다. 표준계약서 조항은 초안이니 한 번은 법률 전문가 검토를 받아두시면 좋습니다.
