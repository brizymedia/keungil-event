# 큰길이벤트기획 갤러리 사진 업로드 서버 설치 (Google Apps Script)

`upload.html` 이 사용하는 무료 백엔드입니다. 설치하면 휴대폰으로 현장에서 바로 사진을 올릴 수 있습니다.

- 웹용 사본(긴 변 1600px, 워터마크 포함) → 저장소 **photos 브랜치**
- `photos/photos.json` 갱신 → 갤러리에 반영
- 갤러리 페이지 다시 만들기 신호 (1~2분 뒤 반영, 실패해도 6시간 안에 자동)

설치는 **한 번만** 하면 됩니다. 그 뒤로는 `upload.html` 만 쓰시면 됩니다.

> **먼저 알아둘 것 두 가지**
>
> **1. 구글 드라이브는 쓰지 않습니다.** 저장소에 올라가는 것은 워터마크가 찍힌 **1600px 사본 한 장**뿐이고, 원본은 휴대폰에만 남습니다. 그래서 드라이브 폴더도, 드라이브 권한도 필요 없습니다. 대신 **휴대폰에서 사진을 지우면 원본은 사라집니다** — 남겨두실 사진은 지우지 마세요.
>
> **2. 사진은 `main` 이 아니라 `photos` 브랜치에 올라갑니다.** 갤러리를 만드는 스크립트가 그 브랜치만 읽기 때문입니다. 예전 스크립트(`review/ym-Code.gs`)는 `main` 에 쓰기 때문에 **사진이 갤러리에 안 나옵니다.** 이 폴더의 `Code.gs` 를 쓰세요.

---

## 1) GitHub 토큰 만들기 (3분)

사진을 저장소에 올리려면 쓰기 권한이 있는 토큰이 필요합니다.

1. https://github.com/settings/personal-access-tokens/new 열기
2. 입력
   - **Token name**: `큰길 사진 업로드`
   - **Expiration**: `No expiration` (또는 1년 — 만료되면 다시 만들어야 합니다)
   - **Repository access**: `Only select repositories` → **`brizymedia/keungil-event`** 선택
3. **Permissions → Repository permissions** 에서 **`Contents`** 를 **`Read and write`** 로 바꿉니다
   (사진 저장과 갤러리 갱신 신호에 둘 다 이 권한을 씁니다. 다른 항목은 건드리지 마세요)
4. **Generate token** → 나오는 `github_pat_…` 문자열을 복사해 둡니다
   **이 화면을 벗어나면 다시 볼 수 없습니다.** 잃어버리면 새로 만들면 됩니다.

> 토큰은 저장소 비밀번호와 같습니다. 카톡·메일로 보내지 마시고, 이 문서나 코드 파일에도 적지 마세요.
> 아래 2단계의 「스크립트 속성」에만 넣습니다.

## 2) 스크립트 만들기 (5분)

1. https://script.google.com → **새 프로젝트**
2. 기본으로 열린 `Code.gs` 내용을 모두 지우고, 이 폴더의 **`Code.gs`** 내용을 붙여넣기
3. 프로젝트 이름을 `큰길 사진 업로드` 등으로 저장
4. 왼쪽 **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가** 로 세 개를 넣습니다

   | 속성 | 값 |
   |---|---|
   | `UPLOAD_PW` | 업로드할 때 칠 비밀번호 (직접 정하세요) |
   | `GITHUB_TOKEN` | 1단계에서 복사한 `github_pat_…` |
   | `GITHUB_REPO` | `brizymedia/keungil-event` |

5. **저장**

## 3) 권한 승인

1. 편집기 위쪽 함수 목록에서 **`권한받기`** 를 고르고 **실행**
2. 권한 요청 창 → 계정 선택 → **고급 → 안전하지 않은 페이지로 이동** → **허용**
   (바깥 인터넷에 연결하는 권한 하나만 씁니다. 드라이브·메일 권한은 요청하지 않습니다)
3. 이어서 함수 목록에서 **`점검`** 을 골라 **실행** → 아래 **실행 로그**에 이렇게 나오면 정상입니다

   ```
   UPLOAD_PW: 있음
   GITHUB_TOKEN: 있음
   GITHUB_REPO: 있음
   photos 브랜치 연결 정상 — 사진 207장, 항목 8개
   ```

   숫자는 그때그때 다릅니다. **「없음」이나 「못 읽었습니다」가 있으면 2단계를 다시 보세요.**

## 4) 웹앱으로 배포

1. 우측 상단 **배포 → 새 배포**
2. 톱니바퀴 → 유형 **웹 앱**
3. 설정
   - 설명: `photo v1`
   - **다음 사용자로 실행: 나**
   - **액세스 권한: 모든 사용자**  ← 휴대폰에서 열어야 하므로 반드시 "모든 사용자"
4. **배포**
5. 표시되는 **웹 앱 URL** 복사 — `https://script.google.com/macros/s/AKfycb…/exec`

> 액세스 권한이 "모든 사용자"여도 아무나 사진을 올릴 수는 없습니다.
> `UPLOAD_PW` 비밀번호가 맞아야 통과합니다.

## 5) upload.html 에 연결

1. 휴대폰에서 `https://큰길이벤트.com/upload.html` 열기
2. 맨 위 **「처음 한 번만 설정」** 칸에 4단계의 웹 앱 주소를 붙여넣고 **저장**
3. 이 기기에만 저장되고 다시 묻지 않습니다. 기기를 바꾸면 한 번 더 넣으셔야 합니다

주소를 잃어버렸으면 스크립트 편집기 **배포 → 배포 관리** 에서 다시 볼 수 있습니다.

## 6) 시험해 보기

1. 갤러리 항목을 고르고, 행사명을 넣고, 사진 1장만 골라 **갤러리에 올리기**
2. "1장 올렸습니다" 가 나오면 성공입니다
3. 1~2분 뒤 `https://큰길이벤트.com/gallery.html` 에서 확인
   — 바로 안 보이면 새로고침(당겨서 새로고침) 한 번 해보세요

---

## 코드를 고친 뒤에는

`Code.gs` 를 고쳤으면 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** 를 해야 반영됩니다.
저장만 해서는 웹 앱에 적용되지 않습니다. **웹 앱 주소는 그대로**라 `upload.html` 은 다시 설정할 필요가 없습니다.

## 자주 나오는 문제

| 증상 | 원인과 해결 |
|---|---|
| "서버가 이상한 답을 보냈습니다" | 배포할 때 액세스 권한이 "모든 사용자"가 아닙니다. 4단계를 다시 하세요 |
| "비밀번호가 다릅니다" | `UPLOAD_PW` 속성값과 입력한 비밀번호가 다릅니다 |
| "깃허브 저장 실패 (401)" | 토큰이 틀렸거나 만료됐습니다. 1단계로 새로 만들어 `GITHUB_TOKEN` 을 바꾸세요 |
| "깃허브 저장 실패 (403)" | 토큰에 `Contents: Read and write` 권한이 없습니다 |
| "깃허브 저장 실패 (404)" | `GITHUB_REPO` 오타이거나, 토큰이 그 저장소를 못 봅니다 |
| "스크립트 속성에 … 가 없습니다" | 2단계의 세 가지 속성 중 빠진 게 있습니다 |
| "UrlFetchApp… 권한이 없습니다" | 3단계 `권한받기` 를 실행한 뒤 **새 버전으로 다시 배포**하세요 |
| 사진은 올라갔는데 갤러리에 안 보임 | 최대 6시간 걸릴 수 있습니다. 저장소 **Actions** 탭에서 「갤러리 페이지 · 사이트맵 자동 갱신」 을 수동 실행하면 바로 됩니다 |
| "다른 업로드가 처리 중입니다" | 두 기기에서 동시에 올리는 중입니다. 잠시 뒤 다시 누르세요 |

## 주의 — 사진을 통째로 다시 만들 때

`scripts/prepare-gallery-photos.mjs` 는 바탕화면 폴더를 기준으로 **갤러리를 처음부터 다시 만드는** 도구입니다.
이걸 돌리면 `photos.json` 이 새로 쓰이면서 **upload.html 로 올린 사진은 목록에서 빠집니다.**
(파일 자체는 브랜치에 남지만 갤러리에는 안 나옵니다.)

둘을 섞어 쓰실 거면, 그 스크립트를 돌리기 전에 말씀해 주세요. 올린 사진을 합쳐서 다시 만들어야 합니다.
